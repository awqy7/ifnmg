# Configuração do Upuai para IFNMG Assistente

## Visão Geral

Este projeto usa o **Upuai Cloud** (PaaS brasileiro) para hospedar o backend FastAPI. O Upuai oferece IP no Brasil, o que é necessário para autenticação no Moodle Virtual2 (`virtual2.ifnmg.edu.br`) sem bloqueios de geolocalização.

## Configuração (Frontend Vercel)

O `backend/.upuai.toml` configura o build e deploy do backend:

```toml
#:schema https://upuai.com.br/schemas/upuai-toml-v1.json

# IFNMG Assistente — backend FastAPI na Upuai Cloud (PaaS brasileira, IP no BR).

[build]
builder = "railpack"

[deploy]
startCommand = "uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}"
healthCheckPath = "/api/health"
healthCheckTimeout = 60
```

## Scripts de Deploy

### `deploy/upuai.sh`

Este script automatiza o deploy para o Upuai Cloud. Ele lê o `.env.local` do seu computador local e aplica as variáveis de ambiente no painel da Upuai.

**Pré-requisitos:**

1. **Criar conta Upuai** (sem cartão, gratuita) em `upuai.com.br`
2. **Instalar CLI do Upuai**: `brew install saiph-ti/upuai-cli/upuai` (ou via binário)
3. **Autenticar**: `upuai login` (OAuth via navegador)

**Executar:**

```bash
./deploy/upuai.sh
```

**O que ele faz:**

1. Valida variáveis obrigatórias (DATABASE_URL, SECRET_KEY, etc.)
2. Lê `backend/.env.local` (se presente) e envia para a Upuai
3. Roda `git push` para o Upuai (mesmo repo GitHub)
4. Imprime a URL `*.upuai.com.br` do backend

### `backend/.env.local`

**NUNCA** version controle este arquivo — ele contém segredos locais!

Crie `backend/.env.local` baseado em `backend/.env.example`:

```bash
cp backend/.env.example backend/.env.local
# Editar com suas credenciais (DATABASE_URL, GROQ_API_KEY, etc.)
```

## Arquitetura (Upuai + Vercel)

| Componente | Hospedagem | IP | Observações |
|-------------|------------|----|-------------|
| **Frontend** | Vercel | Global (CDN) | Interface web em `https://ifnmg.vercel.app` |
| **Backend** | Upuai Cloud (BR) | IP brasileiro | API FastAPI em `https://ifnmg-backend-production.upuai.com.br` |
| **Banco de Dados** | Supabase (Pooler) | IP nos EUA (pooler) | PostgreSQL com
gerenciamento de conexão  |

## Fluxo de Deploy

1. **GitHub** → **Upuai + Vercel**
2. **Upuai** lê `backend/.env.local` e sobe o backend
3. **Vercel** lê `frontend/.env.local` e sobe o Next.js
4. **Frontend Vercel** chama API do backend via `NEXT_PUBLIC_API_URL`
5. **Banco de dados Supabase** acessível pelo backend Upuai (Pooler)

## Ambiente Local (opcional)

Para desenvolvimento local com backend SQLite e frontend Next.js:

```bash
cd ifnmg-assistente
./start.sh  # Roda FastAPI (SQLite local)
# No terminal separado:
cd frontend
npm run dev  # Roda Next.js na porta 3000
```

Acesse `http://localhost:3000` (frontend) + `http://localhost:8000` (backend).

## Segurança e Segredos

### Banco de dados (Supabase Pooler)

```
DATABASE_URL=postgresql+psycopg://postgres.<PROJECT_REF>:<SENHA>@aws-0-<REGIAO>.pooler.supabase.com:5432/postgres?sslmode=require
```

### Senha do Moodle (criptografada)

O `.secret_key` e `encryption.key` do `backend/` criptografam as credenciais do Virtual2.

### Variáveis do Vercel (opcional)

Se você usar o `vercel env pull`, o Vercel injeta `NEXT_PUBLIC_API_URL` automaticamente.

## Solução de Problemas

### "Moodle não autentica" (IP bloqueado)

**Sintoma**: login no Virtual2 falha.

**Solução**: Use Upuai Cloud (IP brasileiro) em vez de Render/Railway (EUA).

### "Health check timeout"

**Solução**: Aumente `healthCheckTimeout` no `backend/.upuai.toml`:

```toml
healthCheckTimeout = 120
```

### "CORS bloqueado"

**Solução**: Adicione `ALLOWED_ORIGINS` no `.env.local`:

```
ALLOWED_ORIGINS=https://ifnmg.vercel.app,http://localhost:3000
```
